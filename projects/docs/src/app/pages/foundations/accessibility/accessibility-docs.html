plim-ui treats accessibility as a baseline requirement. Components use semantic HTML first, keyboard support by default, and ARIA only when native semantics are not enough.

01

Semantic structure

Use the correct HTML elements for landmarks, headings, buttons, and links.

 02

Keyboard and focus

All interactive components must be operable by keyboard with visible focus.

 03

ARIA with restraint

Add ARIA only when it improves assistive technology behaviour.

Keyboard patterns

Component Keys
Button, link Enter / Space activate
Menu, select, autocomplete ↑ ↓ move; Enter select; Esc close
Tabs ← → roving focus between tabs
Dialog, bottom sheet, command palette Esc close; focus trapped while open; focus restored on close
Command palette ↑ ↓ cycle results; Enter select

Each component docs page includes component-specific accessibility notes. Focus rings use --plim-focus-ring-* tokens for consistent visibility.

Forms and validation

  • Associate labels with controls using for and id.
  • Set invalid on both plim-form-field and the control; link errors with aria-describedby.
  • Error messages in plimFormFieldError use role="alert" when shown.
  • Do not rely on colour alone — pair invalid borders with error text.

Overlays and focus

Modal overlays (dialog, bottom sheet, command palette) trap focus while open and restore focus to the trigger on close. Non-modal panels (select, menu, tooltip) return focus to the trigger when dismissed. Body scroll is locked for modal command palette and dialog patterns.

Data display

Tables remain native <table> elements — use th for headers and keep thead / tbody groups. Lists expose role="list" and role="listitem". When data is loading, set aria-busy="true" on the container and use skeleton placeholders or a spinner with an accessible name.

Motion

Transitions use --plim-duration-* and --plim-ease-default. Components respect prefers-reduced-motion: reduce by disabling non-essential animation — for example spinner rotation, sidebar slide transitions, overlay enter animations, and skeleton shimmer.

High contrast and muted content

Interactive states include @media (forced-colors: active) rules where colour carries meaning. Disabled controls use --plim-opacity-disabled; de-emphasized UI can use --plim-opacity-muted.
