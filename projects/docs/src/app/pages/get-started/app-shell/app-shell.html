A typical documentation or admin app combines a sticky header, optional sidebar navigation, and a main content region. plim-ui ships composable primitives for each layer — this guide shows how to assemble them.

Layout structure

Keep landmarks semantic: one <header> via <plim-header>, one navigation <aside> via <plim-sidebar>, and a <main> for routed content. Offset main content in push mode with margin-left: var(--plim-sidebar-width). 

<plim-header sticky>
  <div plimHeaderStart>Brand</div>
  <div plimHeaderEnd>Actions</div>
</plim-header>

<plim-sidebar open mode="push" aria-label="Main navigation">
  <nav plimSidebarNav>...</nav>
</plim-sidebar>

<main>
  <router-outlet />
</main>

Header

Use three projection slots — plimHeaderStart, plimHeaderCenter, plimHeaderEnd — for brand, title, and actions. Set sticky on the host so the bar stays visible while scrolling. See the Header reference for the full API.

Sidebar

Project navigation into plimSidebarNav. Header and footer slots are optional — empty slots are not rendered, so a nav-only sidebar has no phantom dividers. Toggle open and switch between push and overlay modes for mobile. See Sidenav.

Search

For site-wide search, use <plim-command-palette> with a topbar trigger and a Ctrl K shortcut. The parent filters items and handles selected. See Command palette.

Reference app

This documentation site is built with the same pattern: app-docs-topbar, app-docs-shell, and app-docs-command-palette in the docs app source. Use it as a reference implementation when wiring responsive navigation and search.
